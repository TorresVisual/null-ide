# null-activity

Local-only activity tracking (issue #113; engine, dashboard, git statistics, badges and WakaTime import). Activated on `onStartupFinished`; returns `NullActivityApi` (`getIntervals`, `getDailyStats`, `getProjectStats`, `getLanguageStats`, `getSessions`, `recordActivity`, `start/pause/endSession`, `onDidChange`) from `activate`. Deletion is deliberately not on the API. Everything is derived from an append-only interval log: `intervals-YYYY-MM-<windowId>.jsonl` under `globalStorageUri`, one file per window (random id per extension-host launch, never `env.sessionId`, which all windows of one app launch share) so concurrent windows never clobber each other; `stats.ts` keeps two views: the headline (daily/monthly totals, hourly bars, session durations, dashboard `totalMs`) is the union of all windows, while per-project and per-language numbers sum each window's own time via `attributedIntervals` (a WakaTime import only fills gaps live windows left). `Tracker` is a pure state machine over `Heartbeat`s with an injected clock (close rule: a heartbeat within `idleTimeout` (default 900 s, WakaTime's 15 min) of the last one extends the interval and a closing heartbeat ends it at its own time; closes with no heartbeat — pause, shutdown — end at the last heartbeat, so idle time is never credited); only `heartbeatSource.ts`, `statusBar.ts`, `commands.ts` and `extension.ts` import `vscode`. Heartbeats count whether or not the window is focused (parallel agent windows each extend their own interval) and for edits to any open file or untitled document (agent edits to background files count, attributed to the edited file); terminal activity is shell-integration command start/end (no keystroke API exists). Project key is the normalized git remote (worktree-aware), falling back to the folder path. `null-activity.enabled` is the master switch. The only network code is `gistHttp.ts` (opt-in badge publishing); the engine, dashboard and git code have none. The **Coding Activity dashboard** (`null-activity.openDashboard`; the status bar item opens it) is one reused `WebviewPanel` in `dashboardPanel.ts`, fed by the pure `dashboardModel.ts` (`buildDashboardModel` over `NullActivityApi`, plus `parseWebviewMessage` for untrusted webview messages); the CSP shell is `dashboardHtml.ts`. The vanilla-TS UI in `src/webview/dashboard/` (`module: none`, no imports) compiles via `tsconfig.webview-dashboard.json` into the tracked `lib/dashboard.js`; `tsconfig.webview-dashboard-shared.json` compiles `protocol.ts`/`dom.ts`/`model.ts` for the `vm` tests; `lib/dashboard.css` is hand-written; `tsconfig.json` excludes `src/webview`. `sync-local.ps1` copies `lib`. It is read-only (no delete buttons) and adds no engine API. **Git statistics** (`gitLog.ts` pure parser, `gitStatsService.ts` with injected deps and a 60 s per-repo cache, `gitExec.ts` the only place that spawns git): the dashboard shows your commits, distinct files and lines +/− per project and in total. Only commits whose author email equals the repo's `user.email`, on local branches, no merges, for projects in the *open workspace folders* matched by project key (the interval log stores no folder paths, so other projects show "—"); nothing runs in an untrusted workspace. `DashboardPanel` posts the model at once with cached numbers, loads in the background and posts again; the log, `NullActivityApi` and `ActivityService` are unchanged. **Badges** (`badgeModel.ts` + `badgeSvg.ts` pure: total time, average per active day and top language, flat shields-style SVG; `gistClient.ts` + `badgePublisher.ts` with injected deps and no `vscode`; `badgeCommands.ts` is the `vscode` glue): `null-activity.saveBadges` writes the three SVGs to a folder; `null-activity.publishBadges` publishes them to one secret Gist through null-accounts (`getToken(account, ['gist'], …)`, github.com accounts only) after a one-time consent modal, remembers `{ gistId, accountId, owner, hash }` in `globalState` (`null-activity.badge`) and copies the README Markdown. `null-activity.badge.autoPublish` (default off) only refreshes that Gist hourly with a silent token, skips unchanged content, and does nothing while `null-activity.enabled` is off. **WakaTime import** (`wakatimeImport.ts` pure: `convertExport` turns the wakatime.com export's heartbeats into intervals using the export's own `user.timeout`, 15 min when absent; `languageMap.ts` pure name table; `wakatimeProjects.ts` matches each project to a local git repo through `projectIdentity.repoRoot`, else keeps the WakaTime name; `importCommand.ts` is the `vscode` glue): `null-activity.importWakaTime` writes `intervals-YYYY-MM-import-wakatime.jsonl` through `IntervalStore.replaceWindow` via the internal `ActivityService.replaceImported` (not on `NullActivityApi`), so re-importing replaces the previous import and `deleteRange` / `deleteAll` cover it. All categories count; imported lines are 0. Passing a file URI to the command skips its dialogs (used by `import.spec.ts`). **Multiple machines** (#131): `machineId.ts` keeps a random id in `globalStorage/machine.json` (name from `null-activity.machineName`, else the host name); `IntervalStore.read` tags every interval with `machine` (read-back only, like `window`), so per-project/per-language attribution keys on `machine/window` and WakaTime imports of all machines are pooled; `getMachineStats` (`machineTimes`, imports excluded) feeds a Machines card that shows only with more than one machine. Other machines' months are cached whole under `globalStorage/machines/<id>/<YYYY-MM>.jsonl`; `activityBlob.ts` (gzip+base64 JSONL, one blob per machine and month, `activity__<id>__<YYYY-MM>.enc`) and `activitySync.ts` (injected port, no `vscode`) upload this machine's months and replace changed remote ones, every 10 min through `syncLink.ts` and null-sync's optional `syncActivity` (no `extensionDependencies`); one writer per blob, so no conflicts and no duplicates. Deleting data only affects this machine. Design `docs/specs/null-activity-multi-machine-design.md`.
