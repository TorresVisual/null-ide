# null-actions

Status-bar buttons that run shell commands (via a dedicated, deterministically-reused terminal per button — identity is keyed by button id, never by command text, so window reloads and folder reopens don't spawn duplicate terminals) or VS Code API commands. Configured through a settings panel opened via the `$(gear) Actions` status bar item or the `null-actions.openSettings` command (opens as a `WebviewPanel` in the main editor area, not a sidebar view), or directly via the `null-actions.buttons` setting. Shell buttons run through terminal shell integration (`TerminalHost.execute`; falls back to `sendText` when it is absent, waiting up to 3 s on a just-created terminal): the button shows a spinner while running and `$(check)`/`$(error)` plus duration for 8 s after (exit code in the tooltip; clicking a failed result reveals its terminal). Clicking a still-running button follows the per-button `onBusy` setting (`ask` default, `restart` = Ctrl+C then re-run, `show`, `run`); requires VS Code 1.93+. A button with a `problemMatcher` (a matcher name such as `$tsc`, `$eslint-stylish`, `$gcc` or the bundled `$null-rustc`; `$rustc` itself only exists with rust-analyzer installed) runs as a `vscode.Task` (`TerminalHost.runTask`, `ShellExecution`, dedicated panel) instead of the terminal path, so errors reach Problems and clear on the next run; state, exit code and `onBusy` work the same (restart terminates the task, show finds the `Task - Action: <label>` terminal). Only matcher *names* work: the Task API takes no inline matcher objects. Cargo and npm suggestions get matchers by default (npm: `tsc`/`eslint` in the script body). Integration spec `problemMatcher.spec.ts` (`npm run test:integration`, loads null-env too). Supports variable substitution (`${workspaceFolder}`, `${file}`, `${selectedText}`, etc.), priority-ordered status bar placement, an Affinity-style canvas color picker for the button text color, and project-type-detection suggestions (`Cargo.toml`, `CMakeLists.txt`, `*.csproj`, or a one-click "Load npm scripts" button that writes each `package.json` script in as a real persisted button). See `docs/specs/null-actions-design.md`.
