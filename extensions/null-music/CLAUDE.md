# null-music

Local-file music player: view `null.musicView` in its own `null-music` activity-bar container (listed in the Features launcher; `null.musicView.focus` reveals it), status bar item, `Ctrl+Alt+…` media keybindings. The extension host owns all state — `Library` (folders + `.m3u8`, tags and cover art via the in-house `library/tagReader.ts`, JSON cache in `globalStorageUri`), `Queue` (history-aware shuffle, play next/add), `Player` (single position clock, paused session restore under `globalState` key `null-music.session`) and an `AudioOutput`. Sound comes from an `<audio>` element in the sidebar webview (`WebviewAudioOutput`): commands reveal the view and wait for its `ready`, and closing the view stops playback. `isPlaying` is true only after the output reports `play`. There is no provider abstraction; do not add one. The sidebar UI is vanilla TS in `src/webview/music/` (`module: none`, no imports; `tsconfig.webview-music.json` compiles it into the tracked `lib/music.js`, and `lib/music.css` is hand-written — the only hand-edited file in `lib/`). Pure `dom.ts`/`model.ts` are also compiled by `tsconfig.webview-music-shared.json` so `node --test` can load them through `vm` (top-level `function` declarations only). Host and webview share the typed `HostToWebview`/`WebviewToHost` unions in `protocol.ts` (the host pulls them in with a triple-slash reference); `MusicViewController` publishes `player`/`queue`/`library`/`liked` snapshots and the webview only sends intents. Rows carry `data-vscode-context` and the manifest's `webview/context` menu contributes the `null-music.track.*` commands. `sync-local.ps1` copies `lib/`. Designs: `docs/specs/null-music-engine-design.md`, `docs/specs/null-music-player-ui-design.md`; plans: `docs/plans/null-music-engine.md`, `docs/plans/null-music-player-ui.md`.
