# null-startup

Startup profiler (issue #19). Activated on `onStartupFinished`. It reads startup data through the internal command `_null.startup.snapshot`, added by patch 010 (`getExtensionsStatus()` / `ITimerService` are not reachable from the extension API); on a build without the patch (stock VS Code) `snapshotSource.ts` logs once and nothing is recorded — the report panel just shows its empty state. `Capture` writes one `Report` right after startup and rewrites it under the same id ~30 s later (extension status is cumulative, so the later snapshot supersedes the first). Milestones: `windowCreated` (`code/didCreateCodeWindow`), `uiInteractive` (`code/didStartWorkbench`), `workspaceRestored` (`code/didRestoreEditors`, the headline; upstream's `startupMetrics.ellapsed` stops at `didStartWorkbench`, earlier), `extensionsSettled` (end of the last eager activation); launch is `code/didStartMain` / `code/willOpenNewWindow` / `code/timeOrigin`. An extension is *deferred* if it ended after `workspaceRestored`. `intervals.ts` (`incrementalImpact`) makes overlapping phases and activations add wall-clock time once. Pure modules: `buildReport`, `intervals`, `compare` (regression = ≥ 50 ms and ≥ 10 %), `exportReport`, `reportModel` (`buildViewModel`, `parseWebviewMessage`), `sanitize` (activation events with paths reduce to their type); only `snapshotSource.ts`, `reportPanel.ts`, `commands.ts` and `extension.ts` import `vscode`. `ReportStore` keeps one JSON per launch+window under `globalStorageUri/reports`, prunes to `null-startup.retention` (default 20) and never reads, rewrites or deletes files that are not current-version reports. The report is one reused `WebviewPanel` (`null-startup.openReport`); the vanilla-TS UI in `src/webview/report/` (`module: none`) compiles through `tsconfig.webview-report.json` into the tracked `lib/report.js`, `tsconfig.webview-report-shared.json` feeds the `vm` tests, `lib/report.css` is hand-written. Commands: `openReport`, `copyReport` (Markdown), `exportReport` (JSON), `clearHistory`; settings `null-startup.enabled`, `.retention`, `.slowExtensionMs` (default 100, a flag not a verdict). Reports hold only extension IDs, sanitized events, timings and the app version. The integration runner uses vanilla VS Code, so `activation.spec.ts` covers only the degradation path; the real command is checked by hand in a patched build. Design: `docs/specs/null-startup-profiler-design.md`; plan: `docs/plans/null-startup-profiler.md`.
