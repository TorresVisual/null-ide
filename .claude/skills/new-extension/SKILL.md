# New Extension

Scaffolds a new built-in extension under `extensions/<name>/` matching the shape of the existing six (`null-theme`, `null-icons`, `null-tools`, `null-markdown`, `null-cpp`, `null-actions`), then wires it into `.github/workflows/build.yml` so CI actually compiles and bundles it. Do not run the build locally — CI is the only place this repo builds (see CLAUDE.md).

## Steps

1. **Get the extension name and one-line description** if not given as an argument (e.g. `/new-extension null-foo "does foo"`). Names in this repo are lowercase, hyphenated, prefixed `null-`. Ask before dropping the prefix.

2. **Create the directory structure:**
   ```
   extensions/<name>/
     src/
       extension.ts       # activate()/deactivate(), minimal starting point
     package.json
     tsconfig.json
   ```
   Do not create `out/` by hand — it's generated by `npm run compile` and is gitignored.

3. **Write `package.json`**, modeled on an existing extension of similar scope (`null-actions` for a full-featured one with commands/config; `null-theme`/`null-icons` for a static, TS-free one). Required fields: `name`, `displayName`, `description`, `version: "1.0.0"`, `publisher: "null"`, `license: "MIT"`, `engines.vscode` matching the others (`^1.85.0`), `main: "./out/extension.js"`, `activationEvents` (default `["onStartupFinished"]` unless the feature needs a narrower trigger), and `scripts.compile: "tsc -p tsconfig.json"`. Add `scripts.test` only once there's at least one `*.test.ts` file — the convention is `tsc -p tsconfig.json && node --test out/<file>.test.js ...` (see `extensions/null-tools/package.json`). Whatever `out/` this compiles to must never be hand-edited afterward — it's regenerated on every compile.

4. **Write `tsconfig.json`.** Copy the compiler options block verbatim from an existing extension (`target: ES2022`, `module: commonjs`, `outDir: ./out`, `rootDir: ./src`, `strict: true`, `sourceMap: true`, `esModuleInterop: true`, `skipLibCheck: true`). For `include`, list each source file explicitly — this repo does not use a glob like `src/**/*.ts`, every existing extension enumerates files by name — and add each new file here as it's created.

5. **Write a minimal `src/extension.ts`:**
   ```ts
   import * as vscode from 'vscode';

   export function activate(context: vscode.ExtensionContext) {
   }

   export function deactivate() {}
   ```

6. **Install dependencies.** Run `npm install` inside `extensions/<name>/`. Baseline devDependencies: `typescript`, `@types/vscode`, `@types/node` — match the version ranges used elsewhere (e.g. `"typescript": "^5.8.0"`).

7. **Wire into CI (`.github/workflows/build.yml`):**
   - Add a `Compile <name> TypeScript` step (copy the `null-actions` block — `npm ci --ignore-scripts` then `npm run compile`), placed after the other extension compile steps and before "Copy built-in extensions".
   - Add one `Copy-Item -Recurse -Force ide-overlay/extensions/<name> vscode-src/extensions/` line inside the existing "Copy built-in extensions" step.

8. **Flag what's still manual:** CLAUDE.md's "Built-in Extensions" section and repo-layout tree need a new entry — offer to run the `sync-agent-docs` skill for this rather than editing CLAUDE.md by hand. `product.json`'s `configurationDefaults` only needs touching if the extension ships user-facing settings that should have seeded defaults.

9. **Verify.** Run `npm run compile` inside the new extension directory and confirm it produces `out/extension.js` with no errors.
